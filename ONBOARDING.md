# FHF QA Engine — Setup

This repo is the **engine**: GSD Core plus the FHF QA layer (agents, rules, skills, guardrails).
`setup.mjs` turns a folder into the **FHF workspace**, where you actually work.

Don't copy someone else's workspace folder. It carries their credentials and can't be updated.
Clone this repo and run setup instead. It takes about 10 minutes.

All commands are for **Windows PowerShell**. Run each block as shown; don't join commands
with `&&`, because Windows PowerShell 5.1 rejects it.

## 1. Prerequisites

| Need | Check | Get it |
|---|---|---|
| Node.js 24+ | `node -v` | nodejs.org |
| Git for Windows | `git --version` | git-scm.com (GSD hooks use its Bash) |
| GitHub SSH access to `treacyandcoventures` and `lfyagya/fhf-qa-harness-os` | `ssh -T git@github.com` | ask the QA lead |
| FHF VPN | connected | required for the Dev database and backend runs |
| An AI tool | — | Claude Code (recommended), Cursor, or Codex |

Backend lane only: Python 3.10, Oracle Instant Client on `PATH`, Java 17+ (for SQLcl).

## 2. Install

```powershell
cd $HOME
git clone -b fhf-gsd-engine --single-branch git@github.com:lfyagya/fhf-qa-harness-os.git fhf-gsd-engine
cd fhf-gsd-engine
node setup.mjs
```

This creates `$HOME\FHF-GSD-Workspace` beside the engine. To use a different folder, pass it as
an argument: `node setup.mjs D:\work\FHF`. Setup:

1. clones every FHF repo that's missing (it never pulls or changes existing ones);
2. installs GSD Core 1.14.0 into the workspace for Claude Code, Cursor and Codex;
3. adds the FHF agents, rules and skills, plus `CLAUDE.md` / `AGENTS.md`;
4. writes the guardrails: product source is read-only, production smoke artifacts and secrets are
   unreadable, and `git push` is blocked for agents;
5. registers the Oracle connector and the papercuts plugin.

If it prints `Could not clone: ...`, fix your GitHub access and run `node setup.mjs` again.

## 3. One-time steps per person

### a. Cypress lanes (e2e and smoke)

Do this in both `front-end-automation-e2e` and `front-end-automation-smoke`:

```powershell
cd $HOME\FHF-GSD-Workspace\front-end-automation-e2e\CypressFHF\fhf-dashboards
Copy-Item .npmrc.example .npmrc
Copy-Item cypress\environments\cypress.env.example.json cypress.env.json
npm ci
```

Put your own npm token in `.npmrc` and your Okta test credentials in `cypress.env.json`
before running `npm ci`.

### b. Backend lane

```powershell
cd $HOME\FHF-GSD-Workspace\fhf-backend-automation
python -m venv venv
venv\Scripts\pip install -r requirements.txt
Copy-Item config\example_config.ini config\config.ini
Copy-Item tests\example_env tests\.env
```

Fill `config.ini` (`[ORACLEDATABASE]` = Dev database) and `tests\.env` with your own values.

### c. Oracle connector (lets agents read the Dev database schema)

```powershell
winget install Oracle.SQLcl
```

**Open a new terminal** (so `sql` is on `PATH`), connect the VPN, then:

```powershell
sql /nolog
```

At the `SQL>` prompt, use the `[ORACLEDATABASE]` values from `config.ini`:

```
conn -save fhf-dev -savepwd <username>@<hostname>:<port>:<sid>
connmgr list
exit
```

You should see `Connected.` and then `fhf-dev` in the list. Your password stays in SQLcl's own
store, never in a repo. Agents query read-only; DB-writing connector tools are blocked.

### d. Papercuts (optional: logs workflow friction so it gets fixed)

Open the workspace in Claude Code once and accept the **papercuts** plugin prompt. Then:

```powershell
[Environment]::SetEnvironmentVariable('PAPERCUTS_HOME', "$env:LOCALAPPDATA\papercuts", 'User')
cd $HOME\FHF-GSD-Workspace
bun "$HOME\.claude\plugins\marketplaces\papercuts\src\index.ts" setup claude-code --scope repo --apply
```

This needs [Bun](https://bun.sh). Never record customer data or credentials in a papercut.

## 4. Start working

1. Open **`FHF-GSD-Workspace`** (the root, not a lane folder) in your AI tool, and restart the tool
   if it was already open.
2. In Claude Code, approve the `oracle-sqlcl` connector when asked.
3. The first time, run `/gsd-onboard`.

| Work | Command |
|---|---|
| Unclear idea or ticket | `/grill-me`, then `/gsd-discuss-phase` |
| Small fix or single test | `/gsd-quick SERV-1234 ...` |
| Ticket-sized coverage | `/gsd-discuss-phase` → `/gsd-plan-phase` → `/gsd-execute-phase` → `/gsd-verify-work` |
| Where am I? | `/gsd-progress` |

Name the Jira key (SERV, GEARS, LOS, SDX) and the agent reads the ticket through the Atlassian
connector. **You** commit, push, and move Jira tickets.

## Updating

```powershell
cd $HOME\fhf-gsd-engine
git pull
node setup.mjs
```

Re-running is safe: it refreshes GSD Core and the FHF layer and leaves your repos and credentials
alone.

The e2e and smoke lanes are the same repository, cloned twice at different branches.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `'sql' is not recognized` / `'papercuts' is not recognized` | Open a new terminal; installers change `PATH` only for new shells. |
| `The token '&&' is not a valid statement separator` | Windows PowerShell 5.1: run commands on separate lines or join with `;`. |
| Oracle `ORA-12170` / connection timeout | Connect the VPN. |
| `Connection not found: fhf-dev` | The SQLcl save didn't complete; repeat 3c and wait for `Connected.` |
| `Node 24+ required` | Install Node 24, open a new terminal, re-run setup. |
