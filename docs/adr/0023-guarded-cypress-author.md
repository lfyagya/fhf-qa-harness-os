# ADR-0023 — Guarded cypress-author: conventions in, spec writes out

| Field | Value |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-08-30 |

## Context

ADR-0004 removed FHF authoring knowledge from `cypress-author` so it could not emit a
plausible command-first spec that skipped reuse, evidence, scenarios, and `cypress-gate`.
A later allowlist exclusion blocked the Skill invocation entirely. That also blocked the
intended use: Cypress-native conventions (stable selectors, no arbitrary waits, project-shaped
APIs) from the official skill.

Skill matching can still fire before harness routing. A hard block is not required for that
race. A fail-closed guard is: the skill may run, it must not Write/Edit FHF specs, and
`cypress-generator` remains the only writer.

## Decision

- Allowlist `cypress-author` so Cursor, Claude, Codex, Copilot, and Gemini can load it.
- Keep the FHF stop in `subskills/task.md` and add the same guard at the top of `SKILL.md`.
  On FHF Cypress work the skill may **read** author rules as convention input only. It must
  not Write, Edit, create specs, or emit a "generated by Cypress Author" file.
- The parent still follows `new-test` → spawn `cypress-generator`. The generator reads
  `cypress-author` references for Cypress-native quality; FHF architecture and file writes
  stay on the generator → gate path.
- Do not restore `fhf-rules.md`. Do not let this skill become an authoring path.

## Consequences

Allowlist, routing copy, generator instructions, and hook tests change. Spawn budget, gate
ownership, and smoke GET-only do not.
